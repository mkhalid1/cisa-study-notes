# Glossary

Plain-English definitions of terms used in these notes. Domain numbers show where each term is covered in depth.

| Term | Meaning | Domain |
|---|---|---|
| Attribute sampling | Estimates how often a characteristic occurs, such as missing approvals | 1 |
| Audit charter | Board-approved document giving internal audit its authority and scope | 1 |
| Audit risk | Risk of reaching the wrong audit conclusion: inherent x control x detection | 1 |
| Balanced scorecard | Measures performance across financial, customer, internal process and learning perspectives | 2 |
| Batch control totals | Record counts and amount totals compared before and after processing | 3 |
| BIA | Business impact analysis: identifies critical processes, impacts and recovery targets | 4 |
| CAAT | Computer-assisted audit technique | 1 |
| Chain of custody | Record of everyone who handled evidence, when and why | 5 |
| Check digit | A calculated digit that detects keying errors in a code | 3 |
| CISA Associate | ISACA designation for members who passed the exam but lack the experience | Overview |
| CMDB | Configuration management database recording assets and their relationships | 4 |
| COBIT | ISACA's framework for governance and management of enterprise IT | 2 |
| Compensating control | An alternative control used when the ideal one is not feasible | 1, 2 |
| Compliance test | Tests whether a control works as designed | 1 |
| Control risk | Risk that controls fail to prevent or detect an error | 1 |
| Control self-assessment | Management and staff assess their own controls, often facilitated by audit | 1 |
| CPE | Continuing professional education hours needed to keep the certification | Overview |
| Critical path | The longest chain of dependent tasks; it sets the project end date | 3 |
| Data owner | Business manager who classifies data and approves access | 2 |
| Detection risk | Risk that the auditor's procedures miss an error; the auditor controls it | 1 |
| Differential backup | Changes since the last full backup | 4 |
| Digital signature | Hash signed with the sender's private key; verified with the sender's public key | 5 |
| Discovery sampling | Designed to find at least one occurrence of a rare event, such as fraud | 1 |
| DLP | Data loss prevention | 5 |
| DMZ | Screened subnet between external and internal firewalls for public servers | 5 |
| Embedded audit module | Audit code inside an application that captures selected transactions (SCARF) | 1 |
| Escrow | Source code held by a third party, released if the vendor fails | 3 |
| EUC | End-user computing, such as spreadsheets built by users | 4 |
| Hash total | Sum of a non-financial field, used only to detect changes or missing records | 3 |
| Hot site | Fully equipped recovery site, ready within hours | 4 |
| Incident management | Restoring normal service as quickly as possible | 4 |
| Incremental backup | Changes since the last backup of any type | 4 |
| Inherent risk | Risk before any controls | 1 |
| ITAF | ISACA's IT Audit Framework: standards, guidelines, tools and techniques | 1 |
| ITF | Integrated test facility: dummy entity in the live system for test transactions | 1 |
| IT steering committee | Executive body that prioritises and monitors IT investments and projects | 2 |
| IT strategy committee | Board-level body that advises on IT strategy | 2 |
| Mantrap | Two-door entry that admits one person at a time | 5 |
| Materiality | Whether a weakness or error could affect decisions or objectives | 1 |
| OCSP and CRL | Ways to check whether a certificate has been revoked | 5 |
| Parallel run | Old and new systems run side by side during changeover | 3 |
| Parallel test | Recovery site tested with processing while production continues | 4 |
| PIR | Post-implementation review, checking benefits after a system stabilises | 3 |
| Pretest items | Unscored questions trialled for future exams | Scoring |
| Problem management | Finding and removing root causes of incidents | 4 |
| Referential integrity | Every reference in a database points to an existing record | 4 |
| Regression testing | Re-running tests to confirm changes did not break existing functions | 3 |
| Residual risk | Risk remaining after controls | 2 |
| Risk appetite | Amount and type of risk the board is willing to accept | 2 |
| RPO | Recovery point objective: maximum acceptable data loss, in time | 4 |
| RTO | Recovery time objective: how quickly a system must be restored | 4 |
| Scaled score | Raw score converted to ISACA's 200 to 800 scale | Scoring |
| Segregation of duties | Splitting sensitive tasks so no one person controls the whole process | 2 |
| Shadow IT | Technology used without IT's approval or knowledge | 4 |
| SLA | Service level agreement | 4 |
| Stop-or-go sampling | Attribute sampling that can stop early when few errors are found | 1 |
| Substantive test | Tests whether data or balances are correct | 1 |
| UAT | User acceptance testing, with sign-off by users | 3 |
| Variable sampling | Estimates a monetary or quantity value | 1 |
| Write blocker | Device that prevents changes to a drive while it is copied | 5 |
